# v0.1 scope

## In

| Area | Included |
|---|---|
| Documents | `invoice()`, `receipt()` (sent individually, or `{ send: false }` for a Daily Summary), `creditNote()`, `debitNote()` with the Reasons of catalogs 09 and 10 |
| Reporting | `dailySummary()` (reports and voids Receipts), `voidDocuments()`, `waitFor()`, `onTicket`, `retry()` |
| Inspection | `preview()`, `validate()` |
| Lines | Tax Affectation taxed, exempt or unaffected; units NIU and ZZ |
| IGV | `Igv.General` (default) and `Igv.Hospitality` |
| Currency | PEN by default, USD optional |
| Payment Terms | Cash by default; credit with Installments |
| Records | One `record` per operation, including the QR text and the signature hash |
| Testing | `tribu/testing` with `fakeSunat()` |
| Resilience | `timeout`; `retry` (attempts, delay) for pre-send failures only; `recovery` with `Recovery.Confirm` (default) or `Recovery.Resend`, per document type (ADR 0015) |
| Options | `rounding` and `signature`, limited to constants verified in beta (ADR 0018) |
| Rules | The deadlines in ADR 0011's severity model (Invoice 3 days, Receipt individual 5 days, Daily Summary 7 days, voiding 7 days from issue, future dates) |

## Out (later)

- Exports and Invoices without RUC
- Free operations, ISC, ICBPER
- **Detracciones**, perceptions, retentions, advance payments
- Dispatch guide (REST)
- PDF and QR image
- OSE-specific testing (a custom `endpoint` works, but OSEs are not officially tested)
- Rule generator
- Document validity lookup

## Declared limitation

The README must state: *v0.1 does not support detracciones. If your invoices are subject to them, don't use v0.1 for those invoices yet.*
